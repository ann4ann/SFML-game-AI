# MCP Build Server

A Model Context Protocol (MCP) server for managing CMake-based build processes. This server provides tools to configure, build, and test C++ projects with automated error detection.

## Features

- **Configure**: Initialize CMake build configuration in Debug mode
- **Build**: Compile the project using CMake
- **Test**: Run the project's test suite via CTest with detailed output
- **Full Check**: Execute configure, build, and test sequentially with error reporting

## Installation

### Prerequisites

- Python 3.10 or higher
- CMake 3.15 or higher
- A C++ compiler (gcc, clang, or MSVC)
- CTest (included with CMake)

### Setup

1. Clone the repository:
```bash
git clone <repository-url>
cd <project-directory>
```

2. Install dependencies:
```bash
pip install mcp
```

3. Ensure the project structure matches the expected layout (three levels up from the script location for PROJECT_ROOT)

## Usage

### Running the Server

Start the MCP server:
```bash
python build_server.py
```

The server will listen on stdin/stdout for MCP protocol messages.

### Available Tools

#### configure()
Initializes CMake build configuration with Debug mode enabled.

**Returns**: Status message or error output

**Example**:
```
→ configure()
← "Configure successful."
```

#### build()
Compiles the project using the configured build directory.

**Returns**: Build output or success message

**Example**:
```
→ build()
← "Build successful."
```

#### test()
Runs the test suite via CTest with failure details displayed.

**Returns**: Test results or success message

**Example**:
```
→ test()
← "All tests passed."
```

#### full_check()
Executes the complete build pipeline: configure → build → test.

Stops immediately if any step fails and reports the error.

**Returns**: Summary of all steps executed

**Example**:
```
→ full_check()
← "Configure: OK
Build: OK
Test: OK"
```

## Architecture

The server uses **FastMCP** for streamlined MCP server implementation:

- **Async/await pattern**: Non-blocking command execution via asyncio
- **Subprocess management**: Commands run in isolated shell contexts
- **Error detection**: Automatic failure detection based on output content
- **Sequential execution**: `full_check()` runs steps in order with early termination on errors

## Command Execution

Commands are executed asynchronously in the project root directory using Python's `asyncio.create_subprocess_shell()`. Both stdout and stderr are captured and combined for comprehensive output reporting.

## Error Handling

- Configure/build/test failures are detected by checking for "error" or "failed" keywords in output
- `full_check()` returns immediately upon first failure with detailed error information
- Command timeouts and subprocess errors are propagated to the client

## Project Structure

```
project-root/
├── build/              # Generated by cmake
├── CMakeLists.txt
├── src/
├── tests/
└── mcp_server/
    └── build_server.py
```

The `PROJECT_ROOT` is determined relative to the script location (three parent directories up).

## Troubleshooting

| Issue | Solution |
|-------|----------|
| "CMake not found" | Ensure CMake is installed and in your PATH |
| Build fails silently | Check that the project has a valid CMakeLists.txt |
| Tests don't run | Verify CTest is configured in your CMakeLists.txt |
| Permission denied | Ensure the script has execute permissions: `chmod +x build_server.py` |
